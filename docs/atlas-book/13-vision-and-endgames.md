# Vision And Endgames

## Purpose

This chapter turns the current convergence checkpoint into explicit endgames.

It answers:

- why each major lane exists
- what “done” looks like
- what should stay out of scope
- what blocks the next real move

## End-State Shape

The intended steady-state stack is:

- Fitness app lane for Fitness product/runtime truth
- Discord work lane for Discord runtime and Discord-owned workflow state
- ATLAS systems lane for stack coordination, `_stack`, governance, receipts, and doctrine

Shared rules that survive the split:

- no manual deploy by default
- no Discord post before proof
- no `tmp` source-truth fallback
- approval-gated mutation does not reopen by implication
