# Vision And Endgames

## Purpose

This chapter turns the current convergence checkpoint into explicit endgames.

It answers:

- why each major lane exists
- what “done” looks like
- what should stay out of scope
- what blocks the next real move

## End-State Shape

The intended steady-state stack is:

- Fitness app lane for Fitness product/runtime truth
- Discord work lane for Discord runtime and Discord-owned workflow state
- ATLAS systems lane for stack coordination, `_stack`, governance, receipts, and doctrine

Shared rules that survive the split:

- no manual deploy by default
- no Discord post before proof
- no `tmp` source-truth fallback
- approval-gated mutation does not reopen by implication

## Lane Endgames

### Fitness App Lane

- exists to keep product/runtime work bounded to Fitness ownership
- done means Fitness owns product, proof, QA/LLEL, and approved profile hygiene without permanently hosting Discord platform concerns
- should not become the long-term home for unrelated Discord runtime/platform work
- currently blocked only where Discord separation still leaves shared runtime in place
- next valid package:
  - explicit Fitness lane reopen, or approved Fitness Supabase Mutation Pass 1 only

### Discord Work Lane

- exists to give Discord runtime and publication workflows their own home
- done means DiscordOS owns runtime, Discord-owned env, and Discord-owned Supabase classes with explicit Fitness contracts only
- should not depend on hidden Fitness coupling
- bootstrap is complete, but runtime/data migration has not started
- next valid package:
  - bounded DiscordOS code inventory / extraction package

### ATLAS Systems Lane

- exists to own cross-repo coordination, receipts, markers, validation, governance mapping, and restart surfaces
- done means stack state is resumable from docs and receipts rather than memory
- should not become a product-runtime owner
- currently open for docs and governance work
- next valid package:
  - additional governance or book work only when it creates real durable value

## Key Endgames By Theme

### DiscordOS Separation

- done means repo, env, schema, runtime, and cutover all move into governed DiscordOS surfaces with explicit contracts
- should not cut over before contract, schema, and rollback posture are durable
- bootstrap is complete
- currently paused at post-bootstrap implementation sequencing

### Fitness Supabase Hygiene

- done means scoped profile cleanup completes with export, rollback, and approval discipline
- should not become bulk mutation or drift into Discord-owned classes
- currently paused at mutation approval

### Playbook / Core Pattern Convergence

- done means receipt-backed patterns are intentionally routed into doctrine, parked notes, or automation candidates
- should not promote one-off chat instinct into doctrine
- currently open for continued doctrine promotion

### `_stack` Readiness

- done means shared execution commands and deploy authority are explicit, bounded, and fail-closed
- should not absorb product truth
- currently open for planned command design and later implementation

### Automation Lanes

- done means repeated work is classified into safe automation, approval-gated preparation, and never-automate-directly boundaries
- should not turn frequent work into unsafe unattended mutation
- currently open for planning and later bounded command work

### ATLAS Book / Publishing

- done means the book is good enough to restart the stack from docs, receipts, maps, and gates
- should not become a stale brochure disconnected from current receipts
- currently open but lower urgency than before

### Preview / Cache Verification

- done means source drift, generated drift, and preview/cache drift can be separated cleanly
- should not reopen remote verification by implication from local proof
- currently paused at approval gate for remote verification

### Stale Vercel Cleanup

- done means duplicate or stale Vercel surfaces are dependency-checked and removed only when safe
- should not delete by appearance alone
- two stale Spotify-era projects are already deleted
- the two remaining helper Fitness Vercel projects were also deleted on 2026-05-25 after dependency clearance

### Full Clean / Resync Closeout

- done means the convergence wave is actually closed and lane-based work can continue without hidden residue
- should not be forced closed before gated decisions are resolved
- currently intentionally paused
