## Exact Shared-Contract / Consequence-Routing Decision Spine

1. `authoritative-contract-surfaces class`
   - authoritative shared-contract truth lives in the lane-owned and owner-boundary receipts that define the seam itself:
     - `docs/ops/POST-CONVERGENCE-LANE-SPLIT-READINESS-2026-05-24.md`
     - `docs/ops/LANE-SPLIT-EXECUTION-READINESS-2026-05-24.md`

     - `docs/ops/UNIFIED-DISCORD-OS-WORKFLOW-BOUNDARY-2026-05-24.md`
   - these surfaces own the actual contract rules for:
     - proof stays owner-repo first
     - `_stack` owns governed deploy execution
     - Discord publication stays downstream of proof and shipped evidence
     - Fitness auth/profile truth stays Fitness-owned
     - Discord-owned runtime state moves only through explicit contracts and later cutover planning
     - ATLAS records cross-repo consequence rather than owner runtime truth

2. `authoritative-versus-derivative class`
   - authoritative surfaces:
     - lane-owned contract receipts and owner-boundary handoff receipts listed above
   - derivative or mirror surfaces:
     - `docs/atlas-book/11-system-map-graph.md`
     - `docs/atlas-book/12-restart-and-handoff-guide.md`
     - `docs/atlas-book/13-vision-and-endgames.md`
     - `docs/atlas-book/05-receipt-index.md`
   - derivative surfaces are restart aids only
   - they may summarize, route, or mirror contract truth, but they do not become execution or seam authority by being fresher or shorter

3. `contract-inheritance class`
   - lane split readiness inherits shared-contract truth instead of inventing new seam doctrine
   - inheritance order is:
     1. owner-boundary and lane-split contract receipts
     2. proof and release handoff receipts
     3. Discord-facing boundary receipts
     4. ATLAS Book mirrors
   - root may compress and route this truth, but it must not rewrite the owner contract by convenience

4. `missing-contract consequence class`
   - if a required authoritative contract surface is absent for a proposed reopen:
     - the lane does not reopen
     - blocked-work truth routes to the current lane receipt chain as a root-side contract gap
     - the next move stays contract or routing repair, not owner execution
   - missing contract truth is therefore a blocker-state outcome, not permission to improvise from nearby docs

5. `stale-mirror consequence class`
   - if an authoritative contract still exists but the ATLAS Book mirror is stale:
     - trust the authoritative contract
     - refresh only the mirror surfaces
     - do not reopen or widen execution from the stale mirror
   - stale mirrors are read-model defects, not contract defects

6. `contradicted-or-violated-contract consequence class`
   - if a derivative surface or proposed reopen contradicts the authoritative contract:
     - authoritative owner-boundary contract wins
     - root records the contradiction as blocked-work or correction truth
     - downstream proof, deploy, publish, or lane-open assumptions remain invalid until the contradiction is repaired
   - this preserves contract-before-reopen discipline

7. `blocked-work and restart-routing class`
   - blocked-work truth for contract failure routes first to the current lane receipt chain
   - restart truth then routes through:
     - receipt index
     - system map
     - restart guide
     - vision/endgames surface
   - owner repos are not asked to execute merely because ATLAS found a contract deficiency

8. `root-versus-owner boundary class`
   - root-bounded after this pass:
     - contract classification
     - consequence routing
     - blocked-work packaging
     - restart-surface projection
     - marker discipline
   - owner-repo bounded after this pass:
     - proof creation
     - release ledger truth
     - publish execution
     - runtime, schema, bootstrap, cutover, or mutation work
   - this pass does not authorize any owner-side implementation package

9. `reopen-and-non-reopen consequence class`
   - insufficient contract evidence keeps the relevant lane paused
   - a fresh mirror without fresh authoritative contract does not reopen anything
   - a valid reopen still requires both:
     - the pass-4 approval gate
     - the authoritative contract chain for that lane boundary
