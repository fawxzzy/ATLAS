## Exact Multi-Scenario Parity Map Frozen In This Pass

### Exact breadth class that qualifies as multi-scenario release-summary evidence

Multi-scenario release-summary evidence qualifies only when:

1. at least two shipped scenarios exist
2. each scenario independently clears the proof, deploy, and release-ledger floor required for public-strength narration
3. the included scenarios share enough posture that one broader summary does not overstate the weaker scenario
4. the resulting summary can be stated without mixing blocked, partial, and fully shipped units into one claim

### Exact parity-safe grouping rule

Multiple shipped scenarios may be grouped together only when they match on the dimensions that control claim strength:

1. shipped-proof state
2. `_stack` governed deploy-completion posture where applicable
3. owner release-ledger evidence posture
4. public-strength class being claimed
5. level of specificity available for the grouped scenarios

Parity-safe does not mean identical implementation detail.
It means no included scenario would need weaker wording than the group summary actually uses.

### Exact differences allowed without breaking parity

These differences are allowed when the proof and evidence floor still matches:

- different underlying feature or bug topics
- different exact `Report ID` values
- different user-facing wording details
- different shipped-card count inside the grouped set

These differences do not break parity as long as all included scenarios still justify the same summary strength.

### Exact mismatches that force a split

These mismatches force the summary to stay split into one-card or smaller grouped surfaces:

1. one scenario is still blocked or partial while another is fully shipped
2. one scenario has release-ledger evidence and another does not
3. one scenario is only strong enough for exact one-card promotion while another is being used to imply broader grouped breadth
4. one scenario depends on narrower wording than the rest of the group
5. one scenario would require caveat language that the broader summary would hide

### Exact wording strength allowed once parity is met

Once parity is met:

- root-side doctrine may classify the set as parity-safe broader-summary eligible
- owner-side release-summary narration may use broader grouped shipped-work wording
- root mirrors may cite that broader summary posture only after the governed stronger surface actually exists

This does not authorize stronger public wording than the weakest included shipped scenario can support.

## Exact Routing Rule Frozen In This Pass

1. keep parity-safe scenarios grouped only at the highest strength all included scenarios can honestly support

3. do not let the stronger grouped set lift the weaker split set upward
