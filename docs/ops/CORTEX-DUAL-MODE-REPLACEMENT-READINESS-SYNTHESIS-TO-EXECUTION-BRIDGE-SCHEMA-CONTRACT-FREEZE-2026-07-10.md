## Goal

Freeze the first durable schema for the Cortex Bridge: the governed boundary that converts synthesis-side intent into execution-safe packets.

This packet defines the bridge packet contract only. It does not implement a helper, ingest closeouts, execute work, move markers, call models, or widen authority.

## Decision

Adopt this schema identifier for future bridge packets:

```text
atlas.cortex.synthesis_execution_bridge_packet.v1
```

The schema is the required handoff shape between:

- `cortex_synthesis_interface`
- `cortex_bridge`
- `cortex_execution_interface`
- shared ATLAS memory/proof surfaces
- shared Playbook doctrine surfaces

The bridge packet is advisory until a later implementation packet lands a validator or generator.

## Why This Contract Is Next

The lane already has:

- a frozen dual-mode operating model
- an implementation-backed ChatGPT/Codex role inventory
- a manifest-backed `20%` restart posture

The next honest threshold is not execution. It is the bridge contract that prevents synthesis output from becoming unbounded execution authority.

## Non-Goals

This packet does not admit:

- bridge implementation files
- Codex closeout ingestion
- Cortex-generated execution packets
- autonomous execution routing from Cortex state
- replay/evaluation harnesses
- model training or prompt tuning
- owner-repo mutation
- Vercel, Supabase, deploy, or workflow mutation
- secret handling
- hidden transcript ingestion

## Packet Identity Fields

Required identity rules:

- `schema_version` must equal `atlas.cortex.synthesis_execution_bridge_packet.v1`
- `packet_id` must be stable, lowercase, and derived from lane, packet, and date
- `created_at` must use an ISO-8601 timestamp when generated by code
- `source_interface` must be one of the admitted synthesis-side interfaces
- `target_interface` must be `cortex_execution_interface` or `codex_external_adapter`

Allowed `source_interface` values:

- `cortex_synthesis_interface`
- `chatgpt_external_adapter`
- `operator_program`
- `atlas_scheduler`

Allowed `target_interface` values:

- `cortex_execution_interface`
- `codex_external_adapter`
- `atlas_root_receipt_only`

## Source Truth Contract

`source_truth_refs` must include only durable, root-owned truth references.

Allowed source truth classes:

- ATLAS receipts under `docs/ops/**`
- continuity manifests under `docs/memory/initiatives/**`
- ATLAS Book surfaces under `docs/atlas-book/**`
- workflow profile surfaces under `docs/memory/profiles/**`
- root-owned helper output under `tmp/**` when explicitly admitted by the packet
- root-owned source helpers under `ops/**`
- root-owned tests under `tests/**`

Denied source truth classes:

- hidden transcripts
- browser session state
- external chat memory as canonical truth
- secrets or token-bearing files
- `.env*`
- owner-repo worktree state unless admitted as read-only advisory inventory by a prior receipt
- live Vercel or Supabase state unless a specific read-only platform receipt admits it

- `one_packet_only`: boolean

- `platform_mutation_allowed`: boolean
- `secret_access_allowed`: boolean
- `deploy_allowed`: boolean
- `workflow_dispatch_allowed`: boolean
- `marker_movement_allowed`: boolean

For the first bridge generation and validation slices, the required default is:

- `owner_repo_mutation_allowed=false`
- `platform_mutation_allowed=false`
- `secret_access_allowed=false`
- `deploy_allowed=false`
- `workflow_dispatch_allowed=false`
- `marker_movement_allowed=false`

## Authority Denials

Every bridge packet must preserve these denials unless a separate receipt explicitly widens authority:

The bridge must fail closed if durable truth is missing or if an assumption would materially change allowed scope.

## Execution Contract

`execution_contract` must contain:

- `objective`
- `allowed_files`

- `implementation_steps`
- `expected_outputs`
- `non_goals`
- `rollback_or_restore_notes`

`allowed_files` may be empty for docs-only packets, but it must not be omitted.

The contract may recommend commands, but it must not claim commands have run.

- `manual_checks`

## Commit Contract

`commit_contract` must define:

- exact staging discipline
- commit message expectation
- push requirement
- post-push parity requirement
- unrelated-dirt handling

The default staging discipline is: stage exact intended files only.

## Feedback Contract

`feedback_contract` must define how execution proof returns to synthesis memory.

Required fields:

- `validation_result`
- `blockers`
- `risks`
- `next_packet`

The bridge must treat execution feedback as evidence for later adoption, not as automatic marker authority.

## Determinism Rules

Future machine implementations must:

- sort lists deterministically unless source order is part of the contract
- preserve top-level output field order
- emit stable packet IDs for identical inputs
- reject absolute output paths
- reject traversal paths
- write only to explicitly requested output paths
- keep generated local artifacts under `tmp/**`

## Failure-Closed Conditions

The bridge must set `safe_to_execute=false` when:

- durable source truth is missing
- branch or parity is unsafe
- validation has critical or error results outside an admitted cleanup packet
- required scope fields are absent
- owner-repo mutation is requested without authority
- deploy, workflow, platform mutation, or secret handling is requested without authority
- marker movement is requested without a receipt-backed marker decision
- the packet would execute more than one lane
- the selected lane conflicts with active held-lane rules
